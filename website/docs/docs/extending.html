Keeping CMRBench extensible

The framework boundary is dataset → sample → sampling → reconstruction input → model → result → evaluation. Preserve these contracts when adding a component.

For a new dataset, subclass CineMRIDataset, return CineMRISample, and register a factory with DatasetRegistry. Keep physical acquisition masks when present. Define reference meaning, complex phase handling, axes and selection explicitly; do not put model-specific normalization in the reader.

For a new model, implement ReconstructionModel, register a lazy factory with ModelRegistry, and return the candidate plus transform/provenance records. Perform private tensor conversions inside the adapter. Validate supported conditioning and calibration before inference. For a new sampler, implement SamplingProtocol and return SamplingResult with the realized mask, actual R, ACS policy and implementation provenance. Register different source algorithms as explicit implementations rather than overloading a name based on the model.

Growing the dashboard

website/data/experiments.json is the experiment registry. Each entry has a stable ID, category, evidence status, description, settings, limitations, optional metrics_path and optional qualitative asset. The Results selector derives its quantitative options from entries with a metrics file. Keep frozen experiment IDs immutable; add another ID for a changed protocol or dataset.

The current quantitative loader expects a JSON array of subject-level records:

{
  "subject": "Case-001", "model": "RAM",
  "variant_or_implementation": "deepinv",
  "dataset": "inhouse_cine", "experiment_id": "main-v1",
  "sampling": "kt_uniform", "sampling_implementation": "cardiomm",
  "requested_R": 8, "actual_R": 7.1,
  "NRMSE": 0.12, "PSNR": 31.0, "SSIM": 0.90,
  "runtime_sec": 50, "status": "passed",
  "metric_protocol": "cmrbench_recon_metrics_v2_subject_p995",
  "binary_mask_sha256": "<real-mask-hash>"
}

These numbers are schema illustrations, not new benchmark results. Keep a downloadable CSV alongside the JSON. Conditions are explicit and paired joins use subject ID within the selected dataset, physical sampling and protocol. Never pool different datasets, protocols, noise levels or ACS widths under one experiment ID. Noise-SNR and other extra dimensions require extending the condition controls/grouping, or one registry entry per level. That prevents duplicate subject rows from being treated as independent observations.

Qualitative case entries live in cases.json. Include model variant, physical sampling implementation, nominal/actual R when known, display convention, provenance and pairing status. A missing metric stays missing. To add matched reference/ZF/model panels, export a common-mask case with verified run metadata and extend the viewer; archived candidate GIFs do not establish this pairing.

Core statistics are in website/stats.mjs; rendering is in website/app.mjs. There is no framework build or external chart service. Tests cover the statistics and main input validation. Data files and assets use relative URLs so the site works beneath a GitHub project repository path.
