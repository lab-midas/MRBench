Setting up the reconstruction models

MRBench provides adapters, not redistributed model repositories or checkpoints. Acquire the upstream assets under their own terms and place local paths in the appropriate configs/models/*.yaml. Each model keeps its released normalization and reconstruction logic. No adapter receives the reference image as a target, and these experiments do not fine-tune model weights.

RAM

The main table uses ram_deepinv.yaml: DeepInv 0.3.5 and deepinv.models.RAM(pretrained=True) with the canonical multi-coil MRI operator. Install that backend and its compatible torch/CUDA stack in a separate runtime. The backend may acquire pretrained assets on first use; prepare its cache if you need offline operation. A checkpoint path can be configured explicitly.

RAM requires complex sensitivity maps. For prepared cine these are provided by the dataset; for static fastMRI they may be estimated from acquired ACS using the separate preparation path. The adapter adds no external input scaling or measurement noise; the physical Gaussian sigma is fixed at zero in this snapshot. External noise stress tests are labeled separately and retain that model behavior.

ram.yaml selects the alternative official_github backend at RAM commit 0de1617403291e5a28179097795752200e65b82c with DeepInv 0.3.0. Configure its source root separately. It is not the backend in the released main table. Upstream: https://github.com/matthieutrs/ram, https://github.com/deepinv/deepinv.

SDUM

Use the released NVIDIA source at commit 99be712b2e9fd34bf6a2f709373d311354fbda96. Set sdum_source_root, checkpoint and its matching JSON config in sdum_small.yaml, sdum_base.yaml or sdum_large.yaml. Preserve the upstream torch/MONAI and model dependencies in an isolated runtime. The main table evaluates Base; Small and Large are included as adapter capabilities, not additional models in that table.

The adapter preserves cyclic five-frame temporal windows, internal map estimation and RSS magnitude output. Base/Large use acquisition and sampling conditioning. Native Cine categories include nominal R=8/16/24 and the released uniform/Gaussian/pseudo-radial families. External supplied sensitivity maps do not replace the released internal estimator.

VISTA and other shifted physical patterns may require explicit source-supported conditioning, and feasibility still depends on acquired calibration support. These are declared out-of-distribution conditions, not evidence of native training support. Upstream: https://github.com/NVIDIA/NV-Raw2Insights-MRI.

CardioMM

Configure source commit abb6f8a4e293426736467c9859a5f5755c38c8aa, checkpoint and local CLIP directory in cardiomm.yaml. The original validated inference runtime used Python 3.8.20, torch 2.0.1+cu117, NumPy 1.24.4 and transformers 4.30.2. It is separate from the Python >=3.10 core evaluation environment. Use this source checkout on PYTHONPATH for the historical runtime, with its compatible dependencies; GPU execution in that environment has not been repeated locally.

Supply actual lifespan, field_strength, vendor, scanner, modality and view metadata. The values in the model YAML describe the original study and must be changed for your acquisition. The adapter runs framewise, estimates maps internally and preserves the validated batch-one cached text-conditioning path. Retain batch size 1 for the published numerical contract.

The model's uniform/random/radial labels are distinct from the physical sampler. Automatic conditioning accepts representable families; VISTA requires an explicitly declared OOD condition and appropriate calibration rather than a silent relabel. Upstream: https://github.com/wangziblake/CardioMM_MMCMR-427K.

Compatibility and evidence

All models receive canonical measurements and a mask. RAM additionally requires external maps; SDUM/CardioMM use their released internal estimators. Calibration support, acquisition labels, static-versus-cine geometry and sampling categories must be checked for the selected model. The public samplers form a larger set than any one model's native supported conditions.

Changing input data, model assets, dependency versions or conditioning creates a new experiment identity. Record source commits, checkpoint hashes, runtime, physical mask hash, actual R and requested labels. The config hash is provenance, not a substitute for a successful reconstruction or scientific validation.
