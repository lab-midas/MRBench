From the first run to your own reconstruction

Start in the repository root with a Python >=3.10 environment. Installing the package adds NumPy, PyYAML, SciPy, scikit-image and Matplotlib; pretrained models need their separate upstream runtimes and assets.

python -m pip install -e .
python examples/make_toy_data.py
python -m cmrbench.reconstruct --config examples/toy_reconstruction.yaml
python -m cmrbench.evaluate --reconstruction-dir outputs/toy_reconstruction

The toy is an analytic moving ring with complex phase and four sensitivity maps. It demonstrates interface wiring only; its scores are not scientific benchmark results. The zero-filled operator combines coils with the conjugate maps.

Look in outputs/toy_reconstruction/ for config.yaml, experiment_metadata.json, results.csv and a subjects/ directory containing the candidate array and reconstruction metadata. Evaluation writes evaluation/metrics_v2.csv, frame-level metrics, protocol/provenance JSON and QC/animation assets. Source inputs stay unchanged.

Use prepared cine

Copy examples/cine_ram.yaml. Point dataset.manifest to your CSV and dataset.preprocess_root to your prepared arrays, select a subject, and set the number of sensitivity-map coils. Run from the repository root: data/output paths are working-directory relative. model.config is resolved relative to the experiment YAML. Configuration paths are ordinary strings, not environment variable interpolation.

The generic cine path retains every slice and phase. Framewise or temporal-window processing belongs inside the adapter. Change physical sampling in the sampling section, independently of the model selection. An explicit implementation avoids ambiguity between released mask generators.

Use the selected model's Python interpreter for reconstruction, and the core evaluation interpreter for the saved output:

/path/to/ram-python -m cmrbench.reconstruct --config examples/cine_ram.yaml
/path/to/evaluation-python -m cmrbench.evaluate --reconstruction-dir outputs/cine_ram_example

Both processes must be able to import this checkout. RAM/SDUM environments that meet the core package's Python boundary can install it in editable mode. The historically validated CardioMM runtime uses Python 3.8; do not force-install the core package metadata there. Use the source checkout on PYTHONPATH with the documented compatible upstream dependencies, retaining Python >=3.10 for evaluation. That legacy compatibility path was validated on the original server; GPU/model inference is not revalidated by this portable snapshot.

Optional two-stage orchestration

The release copy resolves model interpreters from these environment variables: CMRBENCH_RAM_OFFICIAL_PYTHON, CMRBENCH_RAM_DEEPINV_PYTHON, CMRBENCH_SDUM_PYTHON, CMRBENCH_CARDIOMM_PYTHON and CMRBENCH_EVALUATION_PYTHON. Values must be absolute executable paths. Set PYTHONPATH to this checkout for child processes. Then run:

python -m cmrbench.run_experiment --config examples/cine_ram.yaml

The default is the current interpreter. That fallback is useful only if the selected model and evaluation dependencies are actually installed there; it does not build or switch environments. An explicitly supplied model.environment must agree with the selected runtime. Prefer the separate module commands while setting up a new environment. The toy example uses those separate commands.

Common first-run problems

If files are missing, check the manifest's subject stem and the prepared array names. If model loading fails, check external repository and checkpoint paths in the model YAML. If sampling conditioning is rejected, inspect the physical pattern, calibration geometry and supported model label rather than renaming the pattern. For short cine sequences, explicitly choose valid QC phase indices; the default [6,22] is zero-based and requires at least 23 phases.
